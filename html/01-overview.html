NAI Backend Architecture Overview

What gets created on Kubernetes when you use Nutanix Enterprise AI (NAI) features

How to read this diagram

NAI creates Kubernetes resources across three namespaces. The Envoy Gateway (top) handles all traffic routing. The nai-admin namespace (left) contains the NAI control plane resources. The nai-admin-extensions namespace (right) contains MCP server deployments. KServe (bottom-left) serves local models via vLLM. The AI Gateway (bottom-right) handles unified endpoint routing and model load balancing.

Agent Gateway Features

Provider, Unified Endpoint, MCP Server (local/remote), MCP Connector — each creates specific K8s resources managed by NAI controllers.

AI Inference Features

Model (downloaded from HF/NVIDIA) creates a Model CR + PVC. Local Endpoint creates a KServe InferenceService with vLLM.

Key Insight

NAI is a Kubernetes-native platform. Every UI action creates or modifies Kubernetes CRDs that are reconciled by NAI operators and Envoy Gateway controllers.
